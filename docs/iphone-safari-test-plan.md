# iPhone Safari 테스트 계획

## 목적과 원칙

이 계획은 iOS Safari의 실제 기기 동작을 검증한다. Linux 자동 테스트는 코드·프로토콜 검증에 사용하되, 설치형 PWA, 권한, 마이크와 백그라운드 동작의 통과 근거로 사용하지 않는다.

## 테스트 환경 기록

각 실행에서 아래 정보를 결과와 함께 기록한다.

- iPhone 모델, iOS 버전, Safari 버전
- PWA 설치 여부와 네트워크 조건
- 외부 오디오 입력 사용 여부
- 테스트 빌드/커밋 SHA, 날짜, 실행자

## 공통 준비

1. HTTPS로 제공되는 테스트 환경을 iPhone Safari에서 연다.
2. 기존 사이트 데이터와 마이크 권한 상태를 기록하고 필요한 경우 초기화한다.
3. 주변 소음 수준과 테스트용 발화 스크립트를 기록한다.
4. 녹음 중 화면을 켠 상태로 유지할 수 있도록 자동 잠금을 조정하되, 이 설정도 결과에 남긴다.

## M0 필수 시나리오

| ID | 시나리오 | 절차 | 기대 결과 |
| --- | --- | --- | --- |
| IOS-01 | PWA 설치 | 공유 메뉴에서 홈 화면에 추가 후 실행 | 독립 실행 화면으로 열리고 버전/환경을 확인할 수 있다. |
| IOS-02 | 권한 허용/거부 | 마이크 권한을 각각 허용·거부하고 녹음 시작 | 허용 시 녹음 상태가 시작되고, 거부 시 재시도 안내와 오류가 표시된다. |
| IOS-03 | 포그라운드 녹음 | 화면을 켠 채 10분 이상 발화하며 녹음 | 녹음 상태와 청크/진행 표시가 지속되며 결과를 확인할 수 있다. |
| IOS-04 | 앱 전환 | 녹음 중 다른 앱 또는 Safari 탭으로 전환 후 복귀 | 관찰 가능한 연속 기록은 `observed-continuous`, 확인된 공백은 경고·추정 구간이 있는 `confirmed-gap`, 관찰 불가는 완전성 경고가 있는 `continuity-unknown`으로 정확히 기록·표시된다. |
| IOS-05 | 화면 잠금 | 녹음 중 기기를 잠근 뒤 복귀 | 관찰 가능한 결과를 세 상태 중 하나로 정확히 표시한다. 신호로 공백을 확인할 수 없으면 `continuity-unknown`과 완전성 경고를 표시하며, 연속 녹음을 주장하지 않는다. |

## M1 이후 시나리오

- IOS-06: 네트워크 변동 중 업로드 상태·재시도·실패 안내 및 세션 데이터 손실 여부를 검증한다. 이는 M1 업로드 범위이며 M0은 실제 업로드 성공을 주장하지 않는다.

## M1 이후 회귀 시나리오

- 연속 청크의 순서와 시간 범위가 서버 결과에서 보존되는지 확인한다.
- 관찰 가능한 MediaStream 종료와 비정상적으로 긴 청크 간격이 `confirmed-gap`으로 기록되는지 확인한다. Safari 중단으로 관찰할 수 없으면 `continuity-unknown` 경고를 확인한다.
- mock 처리 상태가 대기·처리·부분·완료·실패로 일관되게 표시되는지 확인한다.
- 결과 노트가 확인된 공백, 연속성 미확인 구간 및 처리 실패를 숨기지 않는지 확인한다.

## 판정과 보고

각 시나리오는 `pass`, `fail`, `blocked`, `not-run` 중 하나로 기록한다. `blocked`와 `not-run`은 통과로 취급하지 않으며, 기기·OS·재현 절차·관찰 결과·스크린샷/로그 위치·후속 Issue를 함께 남긴다. 실제 사용자 음성, 전사문, 식별정보가 포함된 증적은 저장소에 커밋하지 않는다.
